# 新しいスロットを作るとき

ぱびゅドキ！をコピーして始めるのがいちばん早いです。

1. **名前を決めてファイルを複製する**
   - `poker/src/doki.ts` → `poker/src/<名前>.ts`
   - `web/src/lib/doki.ts` → `web/src/lib/<名前>.ts`
   - `web/src/pages/doki.astro` → `web/src/pages/<名前>.astro`
   - `web/src/pages/api/doki/` → `web/src/pages/api/<名前>/`
   - 表は `doki_` を新しい接頭辞に変えた migration を足す（同じ DB に入るので、名前がぶつからないように）
2. **抽選を決める**（`poker/src/<名前>.ts`）
   - 小役の数（合わせて 65536）、払い出し、ボーナスの当たり方、モード、天井
   - `analyze` を新しいしくみに合わせて直し、機械割が狙いどおり（設定1 で 97% 前後〜設定6 で 108% 前後など）になるよう数値を詰める
   - 回して確かめるテスト（`回して確かめても機械割・合算は理論値に近い`）を残しておくと、`analyze` の間違いに気づけます
3. **リールを決める**（`web/src/lib/<名前>.ts`）
   - 21コマの配列。小役はどこで押しても揃うように、ボーナス図柄は目押しが要るように並べる
   - `web/test/doki.test.ts` の「どこで押しても小役はその形に止まる」「適当に押すとボーナスは揃わない」を新しいリールで通す
4. **画面と演出を作る**（`web/src/pages/<名前>.astro`）
   - 絵柄の画像は `web/public/<名前>/sym/` に置く（横 300px 前後の透過 webp）
   - 音は画面の中で合成しているので、`SE` と `BGM` を差し替える
5. **ローカルで遊んで確かめる**：`cd web && npm run dev`

本番（ぱぶびゅ！のダッシュボード）に載せるときは、Worker に API をつなぐ作業と D1 への表の追加が要るので、運営に声をかけてください。

## 気をつけること

- 実在の機種の名前・キャラクター・画像・音・ロゴは使わない（しくみや数値を参考にするのはよい）
- 鍵・トークン・パスワードはコードやファイルに書かない（このリポジトリは公開です）
